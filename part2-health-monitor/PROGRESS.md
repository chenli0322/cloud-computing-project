## What was built (one session, 2026-04-18 → 04-19)

A working end-to-end hybrid Web2 + Web3 health-monitoring pipeline with five
cooperating processes and a live smart contract on Ethereum Sepolia.

### Architecture (5 roles, all running as separate Python processes)

| Role        | Folder                | Entry point                  | Purpose                                              |
|-------------|-----------------------|------------------------------|------------------------------------------------------|
| bootstrap   | `p2p-network/`        | `bootstrap_node.py`          | Rendezvous for peer discovery (not a message broker) |
| iot         | `iot-simulator/`      | `iot_node.py`                | Simulates a wearable; publishes `MSG_SENSOR` every 1.5 s |
| ml          | `ml-model/`           | `ml_node.py`                 | Isolation Forest; emits `MSG_ANOMALY` + SHA-256 event hash |
| bc          | `blockchain/`         | `bc_node.py`                 | Signs + submits `HealthLog.logAnomaly(...)` to Sepolia |
| dashboard   | `dashboard/`          | `server.py`                  | aiohttp WebSocket bridge + static SPA                |

All inter-process traffic uses a single wire protocol:
4-byte big-endian length prefix + UTF-8 JSON (`{msg_type, sender, payload}`).

## Bugs fixed during integration testing

1. **Nonce collision under concurrent submission.**
   Two anomalies arriving within ~1 s caused the second `eth_sendRawTransaction`
   to use a stale nonce and revert.
   *Fix*: introduced `NonceManager` in `blockchain/bc_node.py` — a single
   `asyncio.Lock` + locally-cached `next_nonce`, with rollback on submission
   failure.

2. **`out of gas` reverts for `logAnomaly`.**
   Original gas limit of 180 000 was too tight for the write pattern
   (struct push + two string slots + mapping update + event).
   *Fix*: raised gas limit to 250 000 and simultaneously lowered
   `maxFeePerGas` from 30 gwei to 5 gwei (Sepolia's actual gas price
   stays around 1-2 gwei, so the 30 gwei ceiling was unnecessarily
   locking up per-tx budget). Observed cost dropped from ~0.00036 ETH
   to ~0.00017 ETH per tx.

3. **Dashboard showed failed transactions as "on-chain records".**
   `_submit` previously returned a receipt regardless of `status`, and
   the BC node broadcast `MSG_BC_LOGGED` on every receipt.
   *Fix*: added an explicit `status == 1` check — if the transaction
   reverted, raise and let the upstream handler log it as a failure.

## How to re-run the system

From `part2-health-monitor/`, open five terminals and run:

```powershell
# 1. Bootstrap (do this first)
python p2p-network/bootstrap_node.py --port 9000

# 2. IoT simulator
python iot-simulator/iot_node.py --device-id sim-device-001 --port 9001 --interval 1.5

# 3. ML detector
python ml-model/ml_node.py --port 9002

# 4. Blockchain submitter (requires funded Sepolia wallet + .env)
python blockchain/bc_node.py --port 9003

# 5. Dashboard
python dashboard/server.py --http-port 8080 --p2p-port 9004
```

Then open `http://localhost:8080` in a browser.

Prerequisites: Python 3.10+, Node 18+, a Sepolia wallet with ≥0.01 ETH,
an Infura project ID. Populate `blockchain/.env` (not committed — use
`.env.example` as template) with `SEPOLIA_RPC_URL`, `PRIVATE_KEY` and,
after the first `npx hardhat run scripts/deploy.js --network sepolia`,
`HEALTHLOG_ADDRESS`.
